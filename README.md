# IBM Bob Flaky Failure Investigation Coach

A Bob 2.0 skill that automatically investigates failing pytest tests, classifies each failure into an actionable category, and recommends a concrete next step — so developers spend time fixing problems, not diagnosing them.

---

## Problem

Flaky and ambiguous test failures are a persistent drain on developer productivity. An ICST 2024 industrial case study found that developers lose **at least 2.5% of their productive time** investigating test failures that turn out to be non-deterministic or misclassified.

Existing tools (BrowserStack, TestingBot, mabl) are designed for QA teams running browser-automation suites. They do not help developers triaging everyday **backend or unit test failures**, where the signal is buried in run history, application logs, and source code — not in screenshots or network traces.

---

## Solution

**`flaky-triage`** is a custom Bob 2.0 skill that turns an ambiguous test failure into a clear, evidenced verdict in under a minute.

Given a failing pytest test, the skill:

1. Retrieves the test's run history and computes its flip rate.
2. Reads the test's source code and most recent failure log.
3. Scans for diagnostic signals: timing code (`time.sleep`, `random`), network calls, missing environment variables, or plain assertion failures.
4. Runs a conditional 5-pass probe when the flip rate is borderline (20–70%) and no clear regression signal exists.
5. Classifies the failure into exactly one of five categories:

   | Classification | Trigger | Recommendation |
   |---|---|---|
   | **FLAKY** | Mixed history + timing/random code | QUARANTINE |
   | **REAL BUG** | Consistent pass-then-fail after a code change | FIX |
   | **ENVIRONMENT PROBLEM** | Consistent failure from a missing env var | ESCALATE |
   | **EXTERNAL DEPENDENCY** | Intermittent failure tied to a network call | FIX or QUARANTINE |
   | **NOT ENOUGH INFO** | Too few runs to classify | ESCALATE |

6. Assigns a confidence level (HIGH / MEDIUM / LOW) based on how many independent signals agree.
7. Writes a structured markdown report to `reports/<test_name>_triage.md` and surfaces the same five-part summary in chat.

---

## How Bob Was Used

`flaky-triage` is implemented as a **custom Bob skill** (`.bob/skills/flaky-triage/SKILL.md`). The skill definition encodes the full investigation workflow in natural language, which Bob's Agent mode executes step-by-step:

- **History lookup** — Bob calls `tools/get_test_history.py` via a shell command and reads the structured JSON output.
- **Code and log analysis** — Bob reads the test source and failure logs directly, using its document understanding to identify diagnostic patterns.
- **Conditional rerun** — Bob calls `tools/run_test_n_times.py` only when the history is ambiguous, acting as a tie-breaker without wasting time on clear-cut cases.
- **Report generation** — Bob writes a structured markdown report to `reports/`, then echoes the same five-part summary inline in the chat session.

No custom agent framework or orchestration library was used. The entire investigation loop is expressed as a skill instruction set that Bob interprets natively in Agent mode.

## How to Run

**Install dependencies:**

```bash
pip install -r requirements.txt
```

**Run the test suite to see the failing tests:**

```bash
pytest -v
```

All five tests are designed to fail (or fail intermittently) to provide a realistic triage target.

**Trigger the skill in Bob:**

Open Bob in Agent mode and activate the `flaky-triage` skill on any failing test, for example:

```
The test tests/test_real_regression.py::test_calculate_discount_for_member is failing. Please triage it.
```

Bob will execute the full investigation workflow and produce a report in `reports/`.
